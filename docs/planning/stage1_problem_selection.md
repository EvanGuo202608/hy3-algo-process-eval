## 1 阶段结论

阶段一采用“洛谷检索与难度参考 + 独立形式化规格 + 自编生成器和测试 + 自写参考解”的题集路线。洛谷题目用于确定算法类型、难度和公开来源，不下载、不提交其私有测试数据，也不复制第三方题解。

首批 8 题 MVP 已确定：P1909、P1047、P1094、P1873、P8816、P3366、P3373、P2680。它们覆盖模拟与枚举、区间处理、排序与贪心、二分答案、动态规划、图论与并查集、线段树、树上综合算法。正式版增加 P1090、P7074、P5658、P5022，形成 12 题分层题集。

项目评估的对象是公开、结构化、可核验的解题说明和 C++17 代码，不索取或保存模型的隐藏思维链。每题先建立参考解、生成器、检查器和 rubric，再制作四象限轨迹。任何未运行的实验结果都保持为 `pending`。

## 3 资料依据与使用边界

### 3.1 官方资料

本阶段只将官方页面作为事实依据，算法判断和内部难度属于本项目的技术分析。

1. [洛谷题目难度](https://help.luogu.com.cn/manual/luogu/problem/difficulty)：洛谷把难度划分为八档，同时说明难度带有主观性，仅供训练参考。
2. [洛谷题目搜索](https://help.luogu.com.cn/manual/luogu/problem/search)：题目可按难度、来源和算法等条件筛选。
3. [洛谷题目与评测说明](https://help.luogu.com.cn/manual/luogu/problem/)：部分测试数据会因版权原因不可下载，错误数据下载也受限制。
4. 各候选题的洛谷官方题目页，链接见候选矩阵与 MVP 表。

### 3.2 仓库内容边界

仓库可以保存：题号、标题、官方链接、来源赛事、自己撰写的约束摘要、自编的等价形式化规格、参考解、生成器、检查器、测试元数据和标注。

仓库不保存：洛谷私有测试、批量抓取的数据、他人题解全文、未经许可的完整题面或图片、模型或选手不可见的内部思维链。

如需完全离线复现，优先采用自编等价规格。等价规格必须改写叙事和文字，只保留可公开引用的算法结构，并记录原始灵感链接、改写范围和测试构造方法。

## 4 项目内部难度规则

洛谷颜色只作为外部参考。项目使用四层内部难度，以便解释过程评估为什么会变难。

| 层级 | 判断规则 | 主要评估重点 |
|---|---|---|
| A 基础 | 单一算法核心；实现通常不超过约 60 行；主要风险来自题意、下标和边界 | E1、E5、E8 |
| B 普及 | 需要一种标准算法与清楚的不变量或单调性；错误常能被小反例触发 | E2、E3、E4、E5 |
| C 普及+/提高- | 需要状态设计、图模型或数据结构；正确性依赖多个步骤 | E2、E3、E4、E6 |
| D 提高 | 算法模块组合、实现细节多、弱测试容易漏错；首错定位存在跨步骤依赖 | E2、E3、E4、E5、E6、E7、E8 |

分层时同时记录算法知识点、预期代码长度、参考复杂度、错误模式和测试构造成本。内部层级可以与洛谷颜色不同，但必须解释差异。

## 5 候选题评分方法

每题按五项评分，总分 10 分：算法覆盖 0–2，错误定位价值 0–3，独立测试可构造性 0–2，MVP 实施成本 0–2，引用边界清晰度 0–1。分数用于选题，不代表官方难度或题目质量。

入选还必须满足四项门槛：官方链接可核验、能独立构造测试、能写出无争议参考解、能设计有价值的首错样本。

P14080《最小生成树》没有进入候选矩阵。该题要求评估删去每条边后的最小生成树，工程成本明显高于普通最小生成树，会放大首版题集开发风险。P3366 更适合验证图论、贪心证明与并查集实现。

### 7.1 A01 pack cost

- 最小测试：需求量 1；包装数量大于需求；价格差异极大。
- 关键测试：需求量恰好整除；差 1 才能整除；单位价格低但总价并非最优。
- 预设错误：浮点 `ceil` 转换问题；写成整除下取整；比较单位价格而非总价格。
- 结果对过程错样本：代码枚举总价正确，但说明声称“单位价格最低一定最优”。

### 7.2 A02 interval removal

- 最小测试：`L=0`；单个区间 `[0,0]`；删除整段 `[0,L]`。
- 关键测试：区间相交、包含、相邻、重复；端点 0 和 L。
- 预设错误：把 `[l,r]` 当成半开区间；初始树数写成 L 而非 L+1；重复删除重复扣减。
- 结果对过程错样本：差分代码正确，解释却遗漏闭区间右端点。

### 7.3 B01 pairing

- 最小测试：一个物品；两个物品恰好能配对；所有物品只能单独放。
- 关键测试：大量重复重量；轻重恰好等于上限；最轻与最重不能配时的推进。
- 预设错误：让两个最轻先配；两端指针同时移动；遗漏奇数个物品。
- 结果对过程错样本：双指针代码正确，但证明只凭直觉，没有说明与最重物品配对的交换性质。

### 7.4 B02 cut height

- 最小测试：一棵树；所需木材恰好为某个切割高度产生的值。
- 关键测试：全部等高；高度差悬殊；答案 0；总和超过 32 位整数。
- 预设错误：单调方向反转；找最小可行值；左右边界更新造成死循环；使用 `int` 累加。
- 结果对过程错样本：代码返回最大可行高度，说明却把判定函数描述为随高度单调不减。

### 7.5 C01 rising points

- 最小测试：单点且 `k=0`；两点可直接连接；两点需要恰好 k 个补点。
- 关键测试：相同 x 或相同 y；不可比较点；坐标到 10^9；剩余补点应加入链尾。
- 预设错误：曼哈顿距离少减 1；状态不包含或错误消耗补点；忘记排序；答案忘加剩余 k。
- 结果对过程错样本：代码采用正确 DP，文字把欧几里得距离条件直接等同为任意两点的曼哈顿距离。

### 7.6 C02 minimum network

- 最小测试：单点、单边、两条等权边。
- 关键测试：重边、零权、负权等自编扩展；图不连通；多个 MST；长链并查集。
- 预设错误：未按边权排序；已连通边仍加入；并查集方向或初始化错误；不检查选中 n-1 条边。
- 结果对过程错样本：代码为正确 Kruskal，证明声称“每次选全图最小边必然安全”，却没有排除成环边。

### 7.7 D01 range affine sum

- 最小测试：`n=1`；整段与单点更新；模数为 1。
- 关键测试：先乘后加与先加后乘；多层懒标记；乘 0；大数取模；左右边界相同。
- 预设错误：加法标记未随乘法缩放；乘法标记初值为 0；区间和增加时遗漏区间长度；下传顺序错误。
- 结果对过程错样本：代码正确维护仿射变换，说明却宣称加法与乘法标记可交换。

### 7.8 D02 route upgrade

- 最小测试：两个节点和一条计划；所有边权为 0；所有计划相同。
- 关键测试：链、星形、随机树；最长路径不唯一；候选边只覆盖部分超限计划；n、m 大规模。
- 预设错误：二分判定只检查最长一条路径；树上差分符号或 LCA 扣减错误；升级边不在所有超限路径交集；复杂度退化。
- 结果对过程错样本：代码验证所有超限路径，说明却只用一条最长路径推导候选边。

## 10 标注与数据制作规则

每条轨迹必须先由人确定 gold 标签，再运行评估器。评估器预测不能回填为 gold。

最低字段如下：

```yaml
trace_id: A01-T03
problem_id: A01-pack-cost
source: manual_injection
final_correct: true
process_correct: false
first_error_step: 3
error_types: [E3]
evidence: "步骤 3 声称最低单位价格必然产生最低总价；需求量和包装离散性构成反例。"
annotator: guo_haoyang
review_status: reviewed
```

单错误注入优先于多错误注入。需要多错误时，记录每个修改位置，但 gold 的 `first_error_step` 仍只有一个。所有“结果对/过程错”样本和所有错误样本都应人工复核。

## 14 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 题面或测试版权不清 | 无法公开完整复现 | 使用链接和自写摘要；采用自编等价规格与独立测试 |
| 8 题同时开发 | 纵向链路迟迟不能运行 | 先完成 A01，再逐题扩展 |
| 高难题参考解本身有错 | gold 和测试失真 | 交叉验证、随机对拍、小规模暴力解 |
| 仅靠代码是否通过判断过程 | 无法识别答案对但过程错 | 保留公开结构化步骤，人工制作反例和 gold |
| 单人标注偏差 | 定位指标可信度有限 | 全量复核错误样本；争取教练或另一名选手抽检并报告一致率 |
| 沙盒隔离不足 | 运行陌生代码有安全风险 | 首版只运行仓库内已审代码；阶段三再加入受限执行器 |
